The fastest path from nothing to a running dashboard.

## One command

```bash
npx @viliha/free-admin-dashboard my-app --reactjs
cd my-app
pnpm dev
```

Swap the flag for the edition you want: `--reactjs`, `--nextjs`, `--vuejs`, `--angularjs`,
`--html` or `--laravel`. React is the default, so you can leave it off. It installs with pnpm,
npm, yarn or bun, and the [CLI reference](/docs/installation/cli) has every flag.

Then open [http://localhost:3000](http://localhost:3000).

## Or clone it yourself

If you would rather have the repository and its history, every edition clones and runs the same way.

### Node editions

React, Next.js, Vue and Angular all install the same way. Replace the repository name with the edition
you want.

```bash
git clone https://github.com/myviliha/free-reactjs-admin-dashboard.git my-dashboard
cd my-dashboard
npm install
npm run dev
```

Then open [http://localhost:3000](http://localhost:3000).

| Edition | Repository |
| --- | --- |
| React | `free-reactjs-admin-dashboard` |
| Next.js | `free-nextjs-admin-dashboard` |
| Vue | `free-vuejs-admin-dashboard` |
| Angular | `free-angularjs-admin-dashboard` |

### HTML

No build step and nothing to install.

```bash
git clone https://github.com/myviliha/free-html-admin-dashboard.git my-dashboard
cd my-dashboard
open index.html
```

### Laravel

```bash
git clone https://github.com/myviliha/free-laravel-admin-dashboard.git my-dashboard
cd my-dashboard
composer install
cp .env.example .env
php artisan key:generate
php artisan serve
```

## Starting your own project rather than a clone

`git clone` brings our history with it, which you probably do not want for your own product. The
scaffolder at the top of this page is the answer: it takes the tree without the history, and it also
removes the parts that are ours rather than yours, which a plain copy leaves behind. Our GitHub
Pages workflow, our `FUNDING.yml` and our `CNAME` all go, and `package.json` is renamed after your
folder.

```bash
npx @viliha/free-admin-dashboard my-app --reactjs
```

GitHub's **Use this template** button also works if you want the project to start as a repository.

## What to change first

1. **The brand colour.** One token, in the stylesheet. See [Colours](/docs/customization/colors).
2. **The name and the logo.** `public/images/logo.png` and the wordmark in the brand component.
3. **The footer.** Two environment variables, so you do not have to edit a component. See
   [Configuration](/docs/customization/configuration).
4. **Delete the screens you do not need.** They are files. Removing one means removing its entry from
   the route table, and the test suite will tell you if you miss the sidebar.
